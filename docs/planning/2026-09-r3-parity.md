# Planning — 2026-09 Round 3 parity quick hits (uikit)

**Cycle:** 2026-09 · **Method:** evolution plan (Rounds 1–2 shipped) · **Date:** 2026-09-28

Round 3 of the approved react-uikit vs Radzen comparison plan: the
low/medium parity deltas called out in the cross-learning coverage map
that are cheap, self-contained, and user-visible. Rounds 1 (Consistency)
and 2 (Themes) are merged to `develop` and green on CI/PR #39.

---

## Scope

| Item                     | Radzen parity point                     | Delivered                                                                                                                                                                                                                                                   |
| ------------------------ | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CheckBox `indeterminate` | `TriState` mixed state                  | `indeterminate` prop on `CheckBox` (native `indeterminate` IDL, CSS dash, exposed as `aria-checked=mixed` by the browser); pointer-safe — toggling the indeterminate box checks all, unchecking any clears it (demo: select-all in `demos/pages/forms.tsx`) |
| Imperative dialogs       | `DialogService.Confirm` / `Alert`       | `DialogProvider` + `useDialog()` → `confirm(options)` / `alert(options)` returning promises; resolves `true`/`false` on confirm, cancel, Escape, or close button; concurrent calls **queue** (FIFO); defaults title `Confirm`/`Alert` for accessible name   |
| Tooltip `TargetSelector` | document-level selector delegation      | `targetSelector` prop: one tooltip instance serves every element matching a CSS selector, fixed-positioned next to the hovered/focused target, `aria-describedby` wired on show, dismissed on Escape/scroll/resize                                          |
| Tooltip `Duration`       | `Duration` (default `null` = sticky)    | `durationMs` opt-in auto-dismiss; **default stays sticky** (no timer) — see semantics below                                                                                                                                                                 |
| Validator components     | RadzenTemplateForm validator components | **Decision: do not ship.** See below                                                                                                                                                                                                                        |

## Decisions

### Validators: function API, no declarative components

The cross-learning doc flagged Radzen's declarative validator components as a
P2 follow-up. Decision: **keep the function-based API as the one true
validator surface** — `required`, `email`, `pattern`, `minLength`, `maxLength`,
`requiredTrue`, `range`, `compare`, `custom`, `runValidators`, already exported
from `lib/main.ts` and consumed by `Form` + `useFormField`.

Rationale: the function API is composable, type-safe, testable without DOM,
and covers everything the declarative wrappers do; Radzen needs components
because Blazor has no closures-in-markup story. Adding element wrappers would
double surface area for zero capability. The RadzenTemplateForm-style
"declarative validators" item stays **deferred** unless a consumer asks.

### Tooltip dismissal semantics

Radzen: `Duration=null` (sticky) by default, `Duration` sets auto-dismiss.
Ours before Round 3: already sticky (hover/focus + Escape only, no timer).
Round 3 keeps sticky as default and adds `durationMs` as an opt-in —
behavior change: none for existing callers.
